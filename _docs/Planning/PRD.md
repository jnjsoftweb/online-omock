
# 온라인 오목 게임 웹앱 PRD

NodeJS, NextJS, SQLite를 활용한 온라인 오목 게임 웹 애플리케이션 요구사항 문서

작성일: 2024년 5월 1일

## 1. 개요

본 문서는 NodeJS, NextJS, SQLite를 활용하여 개발할 온라인 오목 게임 웹 애플리케이션의 제품 요구사항을 정의합니다. 오목은 흑백 돌을 번갈아 두며 가로, 세로, 대각선 방향으로 정확히 5개의 돌을 먼저 연결하는 플레이어가 승리하는 전통적인 보드 게임입니다.

이 웹 앱은 사용자들이 온라인에서 실시간으로 오목 게임을 즐길 수 있는 플랫폼을 제공하며, 웹 브라우저를 통해 접근 가능하도록 구현됩니다.

## 2. 제품 개요

### 2.1 게임 설명

오목(Gomoku)은 '다섯 개의 돌'이라는 의미로, 일본에서는 'gomokunarabe(五目並べ)'라고 불립니다. 한국에서는 '오목(五目)', 중국에서는 'Wuziqi(五子棋)'로 알려져 있습니다. 15×15 또는 19×19 크기의 바둑판에서 진행되며, 두 명의 플레이어가 번갈아 가며 돌을 놓고, 가로, 세로, 대각선 방향 중 하나로 연속 5개의 돌을 먼저 배치하는 플레이어가 승리합니다.

### 2.2 대상 사용자

- 오목 게임을 즐기는 모든 연령대의 사용자
- 온라인에서 친구나 다른 플레이어와 게임을 즐기고 싶은 사용자
- 오목 규칙을 배우고 연습하려는 초보자
- 고급 전략을 연마하려는 경험 많은 플레이어
- AI와 대전하며 실력을 향상시키고 싶은 사용자

### 2.3 가치 제안

- 브라우저를 통해 어디서나 접근 가능한 간편한 오목 게임 경험 제공
- 실시간으로 전 세계 플레이어들과 대전할 수 있는 기능
- 친구와 함께 게임을 즐길 수 있는 소셜 기능
- 다양한 난이도의 AI와 연습 가능
- 게임 진행 상황 기록 및 분석 기능
- 모바일 환경 지원으로 언제 어디서나 게임 가능

## 4. 게임 규칙 및 변형

### 4.1 기본 규칙

- 게임은 15×15 또는 19×19 크기의 격자판에서 진행
- 흑돌(검은색)이 먼저 시작하며, 백돌(흰색)과 번갈아 가며 돌을 놓음
- 놓인 돌은 이동하거나 제거할 수 없음
- 가로, 세로, 대각선 방향으로 정확히 5개의 돌을 연속으로 배치하면 승리
- 모든 교차점이 돌로 채워지면 무승부

### 4.2 규칙 변형

초기 버전에서는 기본 규칙만 지원하고, 추후 업데이트에서 다음과 같은 변형 규칙을 추가할 계획:

|변형 규칙|설명|
|---|---|
|렌주룰|흑의 우위를 줄이기 위해 흑에게 특정 제약을 두는 규칙(3-3 금지, 4-4 금지, 장목 금지 등)|
|스왑 룰|흑이 첫 수를 둔 후 백이 돌의 색상을 바꿀 수 있는 옵션을 가짐|
|카로|33 금지와 44 금지 규칙 적용|
|오목|한국식 오목 규칙 (33, 44, 장목(6목 이상) 금지)|

## 6. 기술 아키텍처

### 6.1 프런트엔드

- **NextJS**: React 기반의 서버 사이드 렌더링 프레임워크 활용
- **Socket.io-client**: 실시간 게임 상태 동기화 및 통신
- **Tailwind CSS**: 반응형 UI 디자인
- **HTML5 Canvas**: 게임판 및 애니메이션 구현
- **SWR/React Query**: 데이터 페칭 및 캐싱

### 6.2 백엔드

- **NodeJS**: 서버 런타임 환경
- **NextJS API Routes**: RESTful API 엔드포인트
- **Socket.io**: 실시간 양방향 통신
- **SQLite**: 데이터베이스
- **Prisma**: ORM(Object-Relational Mapping)을 통한 데이터베이스 관리
- **NextAuth.js**: 인증 및 세션 관리

### 6.3 데이터베이스 스키마

|테이블|주요 필드|설명|
|---|---|---|
|User|id, username, email, password, avatar, createdAt|사용자 정보 저장|
|Game|id, blackPlayerId, whitePlayerId, status, winner, createdAt, updatedAt|게임 메타데이터 저장|
|Move|id, gameId, userId, x, y, moveNumber, timestamp|개별 수 정보 저장|
|GameRoom|id, name, hostId, isPrivate, password, status, createdAt|게임방 정보 저장|
|Statistic|id, userId, wins, losses, draws, rating|플레이어 통계 저장|

## 8. AI 구현 계획

### 8.1 AI 난이도

|난이도|알고리즘|특징|
|---|---|---|
|초급|휴리스틱 기반 알고리즘|기본적인 공격과 방어 패턴만 인식, 초보자에게 적합|
|중급|미니맥스 + 알파베타 가지치기|몇 수 앞을 내다보는 전략, 중급자에게 도전적|
|고급|고급 휴리스틱 + 더 깊은 탐색|다양한 전략 패턴 인식, 고급 전술 사용|
|전문가|딥러닝 모델 (선택적)|경험 많은 플레이어도 이기기 어려운 수준|

### 8.2 AI 전략

- 초기 버전에서는 미니맥스 알고리즘과 알파베타 가지치기를 활용
- 게임 상태 평가를 위한 휴리스틱 함수 구현 (연속된 돌의 패턴 인식)
- 오목 특화 패턴 인식 (열린 4, 닫힌 4, 열린 3 등)
- 추후 버전에서는 강화학습 기반 AI 구현 가능성 검토

## 10. 결론

본 PRD는 NodeJS, NextJS, SQLite를 활용한 온라인 오목 게임 웹 애플리케이션 개발을 위한 기본 요구사항을 정의합니다. 이 문서에 정의된 요구사항은 개발 과정에서 사용자 피드백과 기술적 제약에 따라 조정될 수 있으며, 지속적인 업데이트와 개선을 통해 사용자들에게 최상의 오목 게임 경험을 제공하는 것을 목표로 합니다.

이 웹앱은 단순한 게임을 넘어 전 세계 오목 커뮤니티를 연결하는 플랫폼으로 발전시킬 잠재력이 있으며, 지속적인 개발과 콘텐츠 추가를 통해 사용자 경험을 지속적으로 향상시킬 계획입니다.
